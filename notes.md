# Project notes and decisions

## The question
Can consumer complaints filed with NHTSA flag a vehicle safety defect before a recall is
issued, and how much warning would that give?

## Step 1: Data

### Sources
NHTSA Office of Defects Investigation flat files, downloaded from nhtsa.gov/nhtsa-datasets-and-apis:
- **Complaints:** three 5-year chunk files by received date (2015–2019, 2020–2024, 2025–2026)
- **Recalls:** FLAT_RCL_POST_2010.zip. NHTSA split the old single FLAT_RCL.zip into pre- and
  post-2010 files; only post-2010 is needed since complaints start in 2015.
- **Data dictionaries:** CMPL.txt (51 fields) and RCL.txt (29 fields). The data files have no
  header row, so column names come from these.

### Raw sizes
| File | Lines |
|---|---|
| COMPLAINTS_RECEIVED_2015-2019.txt | 489,809 |
| COMPLAINTS_RECEIVED_2020-2024.txt | 418,884 |
| COMPLAINTS_RECEIVED_2025-2026.txt | 210,698 |
| FLAT_RCL_POST_2010.txt | 247,107 |

The recall file has one row per (campaign, make, model, model year) combination, so a single
recall affecting three model years appears as three rows. Counting uses distinct campaigns.

### Known data issue
NHTSA warns that a May 2021 system update retroactively changed manufacturer, make, model, and
component names in some complaint records. Relevant for a project that matches complaints to
recalls on exactly those fields.

## Step 2: Loading and data quality

### Data
- Complaints: 1,106,034 vehicle complaints (2015–2026)
- Recalls: 220,369 vehicle rows covering 13,738 distinct campaigns since 2010

### Parsing
Loaded everything as text first, with quote handling disabled since owner-written narratives
contain stray quote marks. A valid received date (exactly 8 digits) served as a row-integrity
check, since a line break inside a narrative would push fields out of position. **Zero broken
rows** across all files.

### Date choices
- **Complaint date = LDATE (received by NHTSA), not FAILDATE (incident date).** A production
  system only knows about a complaint once it arrives. Using the incident date would leak
  information the model wouldn't have at prediction time.
- **Recall date = RCDATE (manufacturer's defect report received).** The earliest public signal
  a recall is coming, ahead of owner notification (ODATE).

### Leakage filter
Excluded complaint type RC ("recall complaint, result of a recall investigation"), since those
are generated by the recall process itself. No RC complaints appeared in the 2015+ files, so
the filter removed nothing, but it stays in to guard against future data pulls.

### Privacy
The raw files include VINs, consumer cities, dealer contact information, and (since April 2026)
the vehicle operator's name. None of these are selected into processed tables.

### Complaint volume
Roughly 90,000–105,000 complaints per year, dipping to 68,084 in 2021 (likely fewer miles
driven during the pandemic).

### Who initiates recalls
| Initiated by | Campaigns |
|---|---|
| Manufacturer | 12,276 (89%) |
| ODI | 1,353 (10%) |
| OVSC | 109 (1%) |

Manufacturers often recall based on internal warranty data the public never sees, so many
recalls won't be preceded by a public complaint spike. Results are reported separately by
initiator.

### Duplication
A complaint can appear as multiple rows, one per component: 1,103,644 rows covering 787,344
distinct complaints, about 1.4 rows each. Counting uses distinct ODINO, or complaints would be
overcounted by 40%.

### Taxonomy drift
NHTSA renamed its component categories at some point, and the two files sit on different sides
of the change. Complaints mostly use newer labels (ENGINE, SERVICE BRAKES, FUEL/PROPULSION
SYSTEM, VISIBILITY/WIPER); recalls going back to 2010 mostly use older ones (ENGINE AND ENGINE
COOLING, SERVICE BRAKES HYDRAULIC, FUEL SYSTEM GASOLINE, VISIBILITY). The two files also use the
same taxonomy at different depths (complaints mostly top-level, recalls deeper, e.g.
AIR BAGS:FRONTAL:PASSENGER SIDE:INFLATOR MODULE).

Fixed with three rules: take the text before the first colon, truncate at the first comma
(collapsing SERVICE BRAKES, HYDRAULIC/AIR/ELECTRIC into SERVICE BRAKES), then apply an explicit
rename map.

| System | Matchable recalls before | After |
|---|---|---|
| ENGINE | 132 | 719 |
| SERVICE BRAKES | 105 | 1,051 |
| FUEL/PROPULSION SYSTEM | 2 | 822 |
| VISIBILITY/WIPER | 20 | 491 |

A silent failure: nothing errored, the join just returned far fewer matches. Without the fix,
the model would have concluded fuel-system complaints never precede recalls.

### Detection ceiling
Share of recalls since 2017 where the vehicle had *any* complaints on file:

| Initiated by | Recalls | Vehicle has complaints | % |
|---|---|---|---|
| Manufacturer | 8,112 | 5,437 | 67.0% |
| ODI | 559 | 466 | 83.4% |
| OVSC | 61 | 42 | 68.9% |

Tightened to the same vehicle (make, model, model year) with 5+ complaints about the same
system received before the recall was filed:

| Initiated by | Recalls | 5+ prior complaints | % |
|---|---|---|---|
| Manufacturer | 8,103 | 1,102 | 13.6% |
| ODI | 559 | 358 | 64.0% |
| OVSC | 61 | 16 | 26.2% |

Public complaints can meaningfully warn about only about 1 in 7 manufacturer recalls, but
nearly 2 in 3 ODI recalls. This matches how recalls originate: manufacturers mostly act on
internal warranty and engineering data, while ODI opens investigations partly because of
consumer complaints. All model results are reported against this ceiling, split by initiator.

## Step 3: Monthly panel

Each row asks: at the end of this month, for this vehicle (make, model, model year) and system,
will a recall be filed in the next six months?

### Design rules
1. **Activity-based rows.** A row exists only if that vehicle-system had a complaint in the
   prior 12 months. Uses only past information to decide which rows exist; filtering on
   all-time complaint totals would leak the future.
2. **Stop at the first recall.** Post-recall complaints spike from owners receiving notices, so
   all months after the first recall are dropped.
3. **Right-censoring.** The final six months are dropped since their label window isn't
   complete. Left in, they would all look like "no recall followed" and teach false negatives.
4. **Start in 2016**, the first year with a full 12-month lookback.

### Features
Trailing complaint counts (1/3/6/12 months), prior-quarter count for growth, severity counts
(crash, fire, injury, towed), vehicle age, months since first complaint, total vehicle
complaints across systems, this system's share of them, complaints about the same model and
system in other model years, and whether a sibling model year had already been recalled for
this system. All use only information public at prediction time.

### Result
- 2,363,007 rows, 20,681 positive (0.875%), covering 1,667 recalls
- Positive rate rises from ~0.75% (2017–2019) to ~1.1% (2025–2026), a distribution shift
  between training and test periods
- Recalls represented: 1,393 manufacturer, 257 ODI, 17 OVSC

### Known limitation
Only each vehicle-system's first recall since 2010 is modeled. A vehicle recalled for engine
problems in 2012 contributes no rows for a later engine recall. Allowing repeat recalls would
need a cooldown window after each recall instead of a hard stop. Not implemented; this is part
of why ODI recalls are underrepresented relative to the Step 2 ceiling (257 vs 358).

## Step 4: Models

### Split with embargo
- Train: 2016–2021 (1,459,336 rows, 0.799% positive, 921 recalls)
- Gap: 2022, excluded
- Test: 2023 onward (717,696 rows, 1.031% positive, 648 recalls)

A November 2022 row's label depends on recalls through May 2023. Leaving 2022 out as a buffer
keeps any training label from depending on events in the test period.

### Results
| Model | ROC-AUC | PR-AUC |
|---|---|---|
| Base rate | 0.500 | 0.010 |
| Sort by complaint volume | 0.613 | 0.019 |
| Recent surge (3-month count) | 0.611 | 0.020 |
| Sibling year recalled | 0.576 | 0.012 |
| LightGBM | 0.811 | 0.038 |

LightGBM roughly doubles the PR-AUC of sorting by complaint volume, the approach an analyst
without a model would take. Absolute precision stays low (the base rate is 1%), so even the top
alerts are mostly false alarms.

### Alerts per month (test period)
| Alerts/month | Precision | Lift | Recalls flagged in advance |
|---|---|---|---|
| 25 | 8.7% | 8.4x | 28 of 648 |
| 50 | 8.2% | 8.0x | 42 |
| 100 | 7.4% | 7.1x | 76 |
| 250 | 6.5% | 6.3x | 143 |

Alerts can repeat the same vehicle-system across consecutive months, so unique items reviewed
are fewer than the monthly totals suggest.

### What the model is actually learning
Feature importance (gain) was led by vehicle age, make, and system, with raw complaint counts
near the bottom. Separated the two with an ablation:

| Model | ROC-AUC | PR-AUC |
|---|---|---|
| Complaint signals only | 0.705 | 0.025 |
| Structural only (make, system, age) | 0.780 | 0.032 |
| Structural + complaints | 0.809 | 0.038 |
| All (adds sibling-recall features) | 0.811 | 0.038 |

**Most predictive power is structural.** Recalls concentrate in young vehicles, certain
manufacturers, and certain systems. Complaints add only +0.03 ROC-AUC on average.

**But complaints matter most at the top of the ranking:**

| Alerts/month | Structural only | + Complaints |
|---|---|---|
| 25 | 16 recalls | 28 (+75%) |
| 50 | 35 | 42 |
| 100 | 55 | 76 |
| 250 | 107 | 143 |

Structural risk identifies which vehicles to watch in general; complaint surges identify which
specific vehicle-system is about to fail. ROC-AUC averages across the whole ranking and hides
the region a safety team would actually act on.

**Recall expansion check:** removing the sibling-recall features barely changed performance
(0.811 → 0.808), and those features alone scored only 0.663. The model is not just predicting
recalls extending to more model years.

## Step 5: Lead time and who gets caught

Recall-level evaluation at 100 alerts per month: was each test-period recall ever in the top
alerts during the six months before it was filed, and how far ahead was the first warning?

| Initiated by | Recalls | Structural only | Full model |
|---|---|---|---|
| ODI | 132 | 10 (7.6%) | 23 (17.4%) |
| Manufacturer | 507 | 44 (8.7%) | 53 (10.5%) |
| OVSC | 9 | 1 | 0 |

**Adding complaint data more than doubles detection of ODI recalls (+130%) but improves
manufacturer recalls by only 20%.** This confirms the Step 2 ceiling: ODI opens investigations
partly because of consumer complaints, so ODI recalls leave a trail in the complaint data, while
manufacturer recalls mostly originate in internal data the public never sees.

Three steps form one chain of evidence:
1. **The ceiling** (Step 2) predicted complaints would carry signal for ODI recalls far more than
   manufacturer ones (64% vs 13.6% had 5+ prior complaints)
2. **The ablation** (Step 4) showed complaints add little on average but substantially at the
   top of the ranking
3. **This breakdown** shows that top-of-ranking gain lands mostly on ODI recalls

### Lead time
Median warning of about 4 to 4.4 months before the recall is filed. Lead time is capped near
6 months by construction, since the target only looks six months ahead.

### Caveats
- Small counts: 23 vs 10 flagged ODI recalls. The direction is clear, but the exact percentages
  carry wide uncertainty.
- OVSC (9 recalls) is too small to interpret.
- Denominators include only recalls represented in the panel. Recalls on vehicles with no recent
  complaints never enter the evaluation, so these percentages overstate coverage of all recalls.

## Step 6: Fine-tuning on complaint narratives

### Task
Classify complaint narratives into vehicle systems. Purpose: recover the 52,846 complaints filed
only as UNKNOWN OR OTHER, which the panel discards. (An earlier figure of 101,773 counted
complaints with any unknown tag; about half also carry a real system.)

### Data
- 526,414 complaints with exactly one known system; kept the top 15 systems
- Single-system only, so labels are unambiguous. Tradeoff: the model never sees multi-system
  complaints.
- Time split: train before 2023 (44,724, capped at 3,000 per class), validate on 2023 (6,000),
  test on 2024+ (12,000, natural class mix)
- Narratives under 50 characters dropped as too short to classify

### Baseline: TF-IDF + logistic regression
**Accuracy 0.838, macro F1 0.804.** Keywords ("airbag," "brake pedal," "headlight") carry most
of the signal.

Weakest classes: vehicle speed control (F1 0.355, precision 0.239), suspension (0.731),
electrical system (0.735, recall 0.668). Most common confusions: power train ↔ engine, and
electrical → structure (likely power windows, locks, liftgates).

Two caveats:
- **Label noise caps any model's score.** Owners choose categories themselves, and a stalling
  engine could reasonably be filed under engine, power train, or fuel system.
- **Capped training inflates rare classes.** Vehicle speed control is over-predicted partly
  because balanced training makes it look far more common than it is. Both models share this.

### Fine-tuned DistilBERT
distilbert-base-uncased in PyTorch via Hugging Face Transformers. 2 epochs, learning rate 5e-5,
170 warmup steps, max 256 tokens, fp16 on a Colab T4 (about 10 minutes). Uncased because NHTSA
narratives are all capitals. Median narrative is 96 tokens; 6.5% exceed 256 and are truncated.

The pretrained masked-language-model head was discarded and a new classification head trained
for the 15 systems.

Validation macro F1: 0.870 after epoch 1, 0.882 after epoch 2, with validation loss still falling.

| Model (test, natural class mix) | Accuracy | Macro F1 |
|---|---|---|
| TF-IDF + logistic regression | 0.838 | 0.804 |
| DistilBERT | 0.862 | 0.824 |

About 15% fewer errors than the baseline. Gains concentrated where context matters: electrical
system F1 0.735 → 0.798 (recall 0.668 → 0.754), structure 0.757 → 0.838, visibility/wiper
0.819 → 0.851.

**Vehicle speed control stayed broken in both models** (F1 0.355 → 0.372, precision ~0.25). A
much stronger model barely moved it, so the limit is the labels, not the model: owners file
surging and acceleration problems under engine, power train, and speed control interchangeably.
Better models don't fix ambiguous labels.

### Confidence calibration
| Threshold | Coverage | Accuracy |
|---|---|---|
| 0.50 | 95.5% | 88.6% |
| 0.70 | 88.3% | 91.5% |
| 0.80 | 83.7% | 93.0% |
| 0.90 | 76.2% | 94.8% |
| 0.95 | 65.6% | 96.6% |

Accuracy rises monotonically with confidence, so the threshold can be chosen on labeled test data
before being applied to unlabeled complaints.

### Per-class precision at the 0.9 threshold
An overall 94.8% accuracy at confidence ≥ 0.9 hid a class that was wrong nearly half the time:

| System | Precision at ≥ 0.9 | n |
|---|---|---|
| Vehicle speed control | 0.576 | 99 |
| Suspension | 0.869 | 229 |
| Seats | 0.878 | 147 |
| (all others) | 0.910 – 0.993 | |

Kept only systems with precision ≥ 0.90 at the threshold, excluding vehicle speed control,
suspension, and seats.

### Recovering unknown complaints
At confidence ≥ 0.9, 22,175 of 52,846 unknown complaints (42%) cleared the threshold, led by
structure (5,759), electrical (4,812), and visibility/wiper (3,549). After excluding the three
low-precision classes: **20,666 recovered complaints** across 12 systems.

The unknown pool is harder than the test set: 42% cleared the threshold versus 76% of test
complaints. These were filed as unknown partly because they're vague, so the 94.8% test accuracy
likely overstates accuracy on recovered labels.

### Did recovered complaints improve recall detection?
Fed the 20,666 recovered complaints back into the panel (known complaints 731,730 → 752,396),
rebuilt it with the identical SQL, and retrained with identical settings. The classifier was
trained only on pre-2023 labeled complaints and never saw recall data, so its labels cannot leak
recall information.

Sanity check: the original panel reproduced Step 4 exactly (ROC-AUC 0.8105, PR-AUC 0.0383, 76
recalls caught at 100 alerts/month).

| Metric | Original | Augmented |
|---|---|---|
| Panel rows | 2,363,007 | 2,393,219 |
| Recalls represented (all years) | 1,667 | 1,678 |
| ROC-AUC | 0.8105 | 0.8099 |
| PR-AUC | 0.0383 | 0.0390 |
| Precision at 100 alerts | 7.35% | 7.90% |
| Recalls caught at 100 alerts | 76 | 80 |
| — Manufacturer | 53 | 62 |
| — ODI | 23 | 18 |

**Result: no meaningful change.** Recovered complaints made 11 recalls newly visible (6 in the
test period), but detection was essentially flat. The ODI decrease (23 → 18) is within retraining
noise, and the top 100 alerts are fixed slots, so 30,000 new rows can push existing cases out of
the top tier without the model getting worse at them.

Likely reason: the panel already held 731,730 categorized complaints. Adding 2.6% more,
concentrated in structure, electrical, and visibility, isn't enough to change what ranks highest.

**Two separate findings:** the fine-tuned classifier clearly beat its baseline (15% fewer errors,
well-calibrated confidence), but improving the classifier did not improve the downstream task. A
better component doesn't automatically mean a better system, and the only way to know is to
measure the system.

## Decisions log

### Received date over incident date
Complaints are timestamped by when NHTSA received them, not when the incident happened. A live
system only sees complaints after they arrive.

### Recall-generated complaints excluded
Complaint type RC is produced by recall investigations themselves, so it would leak recall
information. Filter kept even though no such rows appeared in this pull.

### Personal information dropped at load time
VINs, cities, dealer contacts, and operator names never enter a processed table.

### Matching on normalized top-level system
Complaints and recalls use different depths and different eras of NHTSA's component taxonomy.
Matching uses the top-level system after comma truncation and an explicit rename map.

### Counting distinct complaints
One complaint can span several rows (one per component). All counts use distinct ODINO.

### Activity-based panel rows
Rows exist only where a complaint arrived in the prior 12 months, a rule that uses only past
information.

### Hard stop at first recall
Post-recall months are dropped to avoid the complaint spike from owner notifications. Cost:
later recalls on the same vehicle-system are not modeled.

### Embargo year
2022 excluded between train and test so no training label depends on test-period events.

### `model` excluded as a feature
Thousands of distinct models would let the tree memorize specific vehicles rather than learn
generalizable patterns. Make and system carry the generalizable part.

### Higher min_child_samples
Set to 200 because with so few positives, small leaves fit noise.

### Gain-based feature importance
Split-count importance overweights high-cardinality categoricals like make.

### Structural-only baseline
Added after feature importance suggested the model leaned on vehicle age, make, and system. The
ablation separated structural risk from complaint signal and showed where complaints actually help.

### Single-system complaints for text classification
Multi-system complaints have no single correct label, so they were excluded from training.

### Uncased transformer
Narratives are all capitals, so a cased model would treat "BRAKE" as a rare, unfamiliar token.

### Per-class precision threshold for recovered labels
A single overall confidence threshold hid a class wrong 42% of the time. Recovered labels were
kept only for systems with precision ≥ 0.90 at confidence ≥ 0.9.

### Measured the downstream effect of fine-tuning
Rather than stopping at classifier accuracy, rebuilt the panel with recovered complaints and
retrained, confirming the original panel reproduced exactly before comparing.
